# SatQuery AI — Day 1 & Day 2 Comprehensive Walkthrough & Integrity Audit

## Executive Overview
SatQuery AI is developed for **SIH Problem Statement 26167** (*"An Interactive Vision-Language Assistant for Multimodal Remote Sensing Image Analysis through Text Queries"* for ISRO / SAC) under two non-negotiable foundational directives:

1. **The Golden Rule (Section 0)**:
   > *"A planned architecture is not evidence that a capability exists. A capability is implemented only after its code executes successfully on the current host machine and passes automated tests."*
2. **The Honesty Rule (Section 0)**:
   > *"Every output must declare the real mechanism that produced it. Never call pseudo-RGB SAR through an optical VLM genuine SAR VQA. Never call raw pixel difference semantic change without a semantic classifier. Never fabricate accuracy, confidence, area, coordinates, benchmarks, or model execution."*

This document reviews the complete architectural, algorithmic, and operational status of Day 1 and Day 2 following the strict implementation-integrity audit.

### 1.3 GeoTIFF Parser & Modality Detection Cascade
In [`src/gateway/raster_inspector.py`](file:///c:/Users/AAKASH.S.S/OneDrive/Desktop/SatQuery%20AI/src/gateway/raster_inspector.py):
- Extracts spatial coordinates, affine transforms, bounding boxes, and projections using `rasterio`.
- Employs a strict **priority cascade** for modality classification:
  1. `explicit_metadata`: Band descriptions or TIFF tags indicating sensor type or polarizations.
  2. `polarization_metadata`: Polarization tags (e.g., VV, VH).
  3. `band_count_heuristic`: 3-band uint8 = Optical RGB; 4+ bands = Multispectral; 1-2 float32 bands = SAR.
  4. `dtype_range_heuristic`: Float32 in decibel backscatter range ($-50 \text{ to } +5 \text{ dB}$).
- Detection method is explicitly recorded as `metadata_assisted_heuristic` or `heuristic` (never falsely claiming authoritative satellite telemetry without direct metadata).

## 3. Scientific Numerical Contracts (Preparation for Day 3)

Implemented in [`src/analysis/numerical_math.py`](file:///c:/Users/AAKASH.S.S/OneDrive/Desktop/SatQuery%20AI/src/analysis/numerical_math.py) and verified in [`tests/test_scientific_contracts.py`](file:///c:/Users/AAKASH.S.S/OneDrive/Desktop/SatQuery%20AI/tests/test_scientific_contracts.py):

### 3.1 Optical Spectral Indices
- **NDVI**: $(NIR - RED) / (NIR + RED)$
- **NDWI**: $(GREEN - NIR) / (GREEN + NIR)$
- **MNDWI**: $(GREEN - SWIR) / (GREEN + SWIR)$
- Fully protected against zero-denominator division and nodata masking.

### 3.2 SAR Polarization Decibel Ratio Physics
- **Critical Rule**: Decibel ($\text{dB}$) values represent logarithmic power. Never compute $VV_{dB} / VH_{dB}$; dividing dB values produces physically meaningless numbers.
- **Linear Backscatter**: $\sigma^0_{linear} = 10^{(\sigma^0_{dB} / 10)}$
- **Linear Polarization Ratio**:
  $$\frac{\sigma^0_{VV, linear}}{\sigma^0_{VH, linear}} = 10^{\frac{VV_{dB} - VH_{dB}}{10}}$$
- **Decibel Difference**: $VV_{dB} - VH_{dB}$

### 3.3 Lee Speckle Filter Domain Pipeline (Section 9)
Filtering must operate in linear power/intensity, not in decibels:
$$\text{SAR (dB)} \longrightarrow \text{dB to linear power} \longrightarrow \text{Lee speckle filter} \longrightarrow \text{linear to dB} \longrightarrow \text{Filtered SAR (dB)}$$
Documented as `PENDING_DAY_3`.

### 3.4 Scene-Adaptive Water Thresholding
- No universal constant threshold (e.g. $VV < -17 \text{ dB}$) is claimed as an absolute physical law.
- Planned Day 3 implementation computes scene statistics $\rightarrow$ bimodal/adaptive threshold $\rightarrow$ candidate water mask $\rightarrow$ records threshold and method in provenance metadata.
